# MiraRedeem

Secure one-time redeemable items for the Mira Minecraft plugin ecosystem.

## Current behaviour

- Redeem items are generated by MiraRedeem and tagged with protected persistent metadata.
- Visible name/lore does not determine what command executes.
- Each item is validated against its canonical configured definition before redemption.
- Right-clicking a valid redeem executes its configured command(s) as console.
- Success feedback is sent to the player after command dispatch.
- Exactly one redeem item is consumed only after successful command dispatch.
- Modified or forged-looking items are rejected and are not consumed.
- Anvil, grindstone, smithing, crafting and enchanting modification paths are blocked for tagged redeem items.

## Admin commands

- `/miraredeem give <player> <redeem> [amount]`
- `/miraredeem list`
- `/miraredeem reload`
- Alias: `/mredeem`

Permission: `miraredeem.admin` (OP by default)

## Test redeem

The default config includes `pyro_axe`:

```yml
commands:
  - "mitem give %player% pyro_axe"
```

Test with:

```text
/mredeem give <player> pyro_axe
```

Then have that player right-click the voucher. MiraRedeem dispatches `mitem give <player> pyro_axe` as console, sends the configured success message, and consumes one voucher.

## Placeholders

Configured console commands support:

- `%player%`
- `%username%`
- `%uuid%`

## Security note

A random HMAC signing secret is generated automatically on first startup and stored in `config.yml`. Do not change that secret after vouchers have been issued, otherwise previously issued vouchers will no longer validate.
